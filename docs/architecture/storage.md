# SQLite registry

One `rit.sqlite3` under `--data-dir`, else `RIT_DATA_DIR`, else Linux XDG data (`$HOME/.local/share/rit` fallback), macOS `~/Library/Application Support/rit`, or Windows `%LOCALAPPDATA%/rit`. No cwd fallback. Explicit paths may be relative; registration forbids parent traversal and known in-repository data paths. File permissions depend on OS and umask; hardened storage access control is not implemented. Network filesystems are unsupported.

Bundled `rusqlite` uses foreign keys, five-second busy timeout and FULL synchronous mode. New databases use SQLite's default rollback journal; RIT does not switch an existing database's journal mode. Transactions are short, single-writer-aware and SQLite serializes writers. Database creation and schema-0→1 migration are inside an immediate transaction, using `PRAGMA user_version`; future versions are rejected without deleting data. `repositories` holds ID, unique common directory, name, format, first-location bare flag and timestamps; `repository_locations` holds FK to repository, unique UTF-8 path, per-worktree Git directory, kind and first/last seen time. No commits or current statuses are stored.

Listing and ID lookup open an existing registry read-only and do not create a missing database. Doctor performs a read-only `quick_check` for an existing database and reports uninitialized without creating it. A quick check is not a full schema or media integrity audit. Full migration fault injection, concurrent stress and backup/restore are not complete. For backup, use SQLite's online backup facilities or a documented quiesced consistent copy; do not copy an open DB while ignoring its journal. RIT does not implement backup or automatic recovery in this phase.

## Phase 2.1 work in progress — important compatibility warning

The experimental storage boundary currently permits registry operations only on Linux. Other platforms fail closed, including macOS and Windows; this is not a claim of cross-platform security. On Linux, the data directory must be owner-only and safely rooted through trusted ancestors, and existing database/sidecar files must be owner-only, single-link regular files. Earlier unmarked version-1 databases are **not** adopted automatically. After making a consistent backup and arranging safe permissions, inspect with `rit storage verify --json`; `rit storage adopt-legacy --confirm` explicitly adopts only the exact recognized schema. If a hot-journal recovery error occurs, preserve the database and its journal together: current automatic recovery is blocked. See `docs/phases/phase-02-remediation-report.md`, `docs/security/storage-threat-model.md`, and ADR 0003. This branch is not accepted for production or Phase 3.
