# Phase 10 — local protocol foundation

A bounded newline-delimited stdio JSON-RPC server implements MCP initialization negotiation (server version 2025-03-26), ping and an empty tools list; route middleware explicitly allows only these public discovery methods. Every other method, including tools/call, is denied before dispatch; no privileged tools, credential handling, HTTP listener or production operation exists. Rust protocol/transport integration tests exercise discovery and denied calls. Python and TypeScript have transport-injected request-client foundations; A Python SDK-to-stdio integration test passed; TypeScript typecheck is not yet established. This is a discovery prototype, not an MCP-complete implementation, security review, production API, or a substitute for central actor authorization. The middleware must be replaced/extended with the Phase 3 common authenticated policy before tools are added.

## V2 continuation — modern discovery and real client interoperability

The protocol prototype now accepts the modern 2026-07-28 `server/discover` and per-request version metadata on its small public discovery surface, reports unsupported modern versions, and retains legacy 2025-03-26 initialization. Its supported-version advertisement concerns this discovery subset; full MCP base-pattern and SDK conformance is **not verified**. All `tools/call` operations remain denied, and there is no HTTP API or shared authenticated application service. A transport-injected Rust client was added and tested against a real stdio server. The TypeScript client was typechecked with TypeScript 5.7.3 and exercised against that server for discovery and denied tool calls; Python interoperability likewise covers only legacy discovery and denial. No SDK implements authenticated product operations, retries, pagination or full validation. Current protocol source: https://modelcontextprotocol.io/specification/2026-07-28/server/discover and https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning.
