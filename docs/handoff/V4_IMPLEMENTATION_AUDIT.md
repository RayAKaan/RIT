## Newly reproduced genuine regression

On a disposable Git repository, configure an external clean filter in `.git/config` and `.gitattributes`, modify a matching file, and invoke `rit repo diff PATH --json`. Git executes the configured clean-filter shell command despite `--no-ext-diff` and `--no-textconv`: these flags do not suppress clean filters during worktree hashing. This violates the intended V3 safety boundary. Status may also hash content in some cases. Fix or fail closed before exposing those operations; do not mistake a preflight-only check, which can race concurrent config changes, for an OS execution sandbox. Other Git subprocess behavior, hooks, attributes and partial clones must be evaluated before adding mutations.

## Design constraint

Git refs and manifests are coordination metadata, never authentication. Git `worktree add` can run checkout hooks, clean/smudge filters, and configured commands; `merge-tree` can run custom drivers. Any implementation must either demonstrably suppress these paths without unsafe races or remain explicitly unavailable. A worktree is not an OS sandbox. Preserve data and never use force removal or unsafe registry bypass.

## Workspace design and traceability update

The implemented limited Linux x86-64 provider writes an unauthenticated JSON manifest blob under `refs/rit/workspaces/<uuid>/manifest`, initially `provisioning`, then `ready` or `no_checkout`, with compare-and-swap updates. It allocates `refs/heads/rit/workspaces/<uuid>` via expected-zero `update-ref` before `worktree add --no-checkout`; interruption leaves discoverable metadata and/or an orphan branch rather than cleaning up user data. `git push --all` can push these branches. Manifest claims must be reconciled against Git inventory and are not a principal or authorization record.

Materialization uses bounded `ls-tree` and raw `cat-file` content, `read-tree` into the new worktree's index, and exclusive no-follow descriptor-relative file creation, not checkout. It refuses symlinks, submodules, configured filters, checkout-affecting attributes, autocrlf, oversized/non-Unicode/unsafe paths and other unsupported content; these worktrees remain explicitly `no_checkout`. Hooks are disabled and Linux seccomp prevents child process creation for these Git operations; this is a narrow execution mitigation, not a sandbox. Parent directories must be owner-only with trusted non-symlink ancestry. No destructive workspace removal is exposed; Git's removal can discard ignored files and invokes another Git process. Same-OS-user concurrent interference, filesystem races, materialization semantics, permissions and crash windows still require independent review.

`crates/rit-git/src/process.rs` is the provider, `WorkspaceService` in `rit-application` is the application boundary, `rit workspace` is the CLI, and `creates_and_reconciles_five_actual_rit_workspaces` creates five worktrees through RIT before user-like fixture edits and commits, checks branch independence/lock/unlock and simulates moved/interrupted/orphan conditions. `filtered_workspace_is_real_but_explicitly_not_checked_out` verifies filter refusal. This is not the complete acceptance suite: removal and the broader lifecycle state machine remain disabled/incomplete.

The status/diff clean-filter regression is mitigated on Linux x86-64 using root-owned `setpriv` and a seccomp BPF child-process restriction; other platforms fail closed for these operations. Dirty submodules are inspected separately with the same restriction. This is not a general isolation provider or native platform validation; configured filters may make the Git operation fail rather than producing a diff. `worktree_hashing_never_executes_repository_clean_filter` reproduces the adversarial configuration and checks its marker remains absent.

## Native notification traceability

`rit-application/src/watcher.rs` uses the maintained `notify` recommended native watcher, disables symlink following, watches the actual Git inventory, attaches a workspace ID only when matched to a RIT manifest, normalizes file events, suppresses exact duplicates for 150 ms, uses a bounded nonblocking queue and reports overflow/rescan requests. Errors trigger restart; the CLI periodically refreshes watches and re-observes Git. `rit activity watch` defaults to notifications; an explicit `--count` retains V3 finite snapshot polling. Both JSON and human-formatted output are supported, with `--duration-ms` for bounded runs. No authenticated actor or durable historical event is invented; events missed during downtime or overflow are unrecoverable. Native rename pairing is only reported when supplied in one event; Git stage/commit/branch transitions are reflected in reconciliation snapshots, not yet normalized as dedicated events. Restart/drop cleanly releases the provider; OS termination remains process shutdown. Tested Linux only, no cross-platform acceptance claim.

`bounded_queue_reports_overflow_and_restart_reconciles` exercises real overflow and restart through the application provider; `native_watcher_observes_concurrent_changes_in_rit_created_workspaces` exercises five RIT-created worktrees, concurrent writes, native events, correct workspace correlation and periodic Git reconciliation via CLI. Neither proves complete notification history nor every OS event category.

## Dependency traceability

`Git::source_snapshot_revision` now resolves explicit branch/commit to a Git commit; `source_snapshot_worktree` enumerates tracked plus nonignored untracked source files, reads descriptor-relative with no-follow, checks file changes during reads and computes a bounded content digest. Worktree observations are explicitly non-atomic, can become stale immediately, omit ignored files and separately staged bytes, and report skipped missing/symlink/nonregular paths. Only Linux x86-64 worktree reads are enabled. `GitReadService` and `rit dependencies`/`rit impact` select HEAD, commit, branch, current worktree or a reconciled managed workspace; `impact --workspace` without files uses current Git status separately and thus is non-atomic.

`rit-analysis` adds source SHA-256, parser versions, resolution method, snapshot identifiers, bounded cycle diagnostics and conservative local Go module/package edges from `go.mod`. Go build tags, vendoring, workspaces, replace directives and multiple-module ambiguity are not fully resolved; Python/TS remain heuristic and dynamic imports, symbols, tests, TypeScript aliases, JavaScript/TSX, explicit file-set and public-interface impact are incomplete. `complete` remains false. CLI tests `analyzes_selected_commits_and_go_module_packages_with_evidence` and `workspace_analysis_reads_non_atomic_tracked_and_untracked_sources_without_following_symlinks` cover immutable revisions, Go edges, cycles, real RIT workspace edits/untracked files, symlink omission and reverse impact. No graph cache or durable invalidation is claimed.

## Conflict simulation traceability

`Git::simulate_merge` runs real `git merge-tree --write-tree --messages -z` with Git object output redirected to a temporary directory and original objects used only as alternates. It resolves commits, reports all best merge bases, base-relative changed paths, Git conflict stages and message types, and removes the scratch object store after the call. No branch or worktree is changed and the result tree is explicitly ephemeral. Configured custom merge drivers are refused, process creation is blocked by the Linux x86-64 seccomp restriction, and unexpected Git stderr fails closed; no independent security review is claimed. `ConflictService` obtains bounded source blobs and provides Tree-sitter both-side declaration-hash evidence and binary/gitlink categories; these are advisory and incomplete. CLI: `rit conflicts simulate --repo PATH --left REF --right REF --json`.

`conflict_simulation_is_isolated_and_reports_git_stages_and_structural_evidence` creates two worktrees via RIT, commits divergent Python and binary changes, checks real stages and structural evidence, verifies unchanged target/refs/worktrees and refuses configured custom driver without executing its marker. Clean divergent merge was also manually checked. No durable conflict IDs, complete rename/delete/add classification suite, semantic reasoning, Mergiraf, apply, or candidate publication is claimed.

## Bounded raw-content checkpoint traceability

`Git::content_checkpoint_create` and `GitCheckpointService` capture the actual managed worktree's original raw index blob and staged Git index entries separately from raw tracked worktree bytes, selected nonignored untracked files (`--include-untracked`) and exact ignored files (`--include-ignored PATH`). Regular content, executable-bit evidence, deletions and raw symlink targets are captured without following links or invoking clean filters, using bounded no-follow reads and Git `hash-object --no-filters`. A synthetic unauthenticated Git commit whose parent is the base commit retains a manifest blob, raw index blob, staged-object tree and raw-worktree-object tree; expected-zero refs are under `refs/rit/content-checkpoints/<uuid>`. The commit/ref is coordination data, not authorization. Failed/interrupted creation may leave unreachable Git objects; it never deletes source files or replaces a checkpoint ref.

The index and HEAD are rechecked, but multi-file capture is non-atomic and `complete=false`. Limits: 500 paths, 1 MiB/file and 8 MiB total raw content; selected ignored files only, no special files, no complete submodule contents/dirty state, no guaranteed LFS object availability, no split-index support beyond index entries, no full POSIX ACL/xattr/mtime/hardlink metadata. Explicitly selecting files may persist sensitive user content in Git; this is not credential storage. Reads can become stale immediately; no authenticated provenance is claimed. Restore and deletion remain disabled.

`checkpoint list/inspect/verify` rediscover the commit after process restart. Verification uses Git fsck with commit-graph/multi-pack-index checks disabled for child-process restriction, and separately checks parent/base, root layout, index blob and exact manifest/tree entry mapping; this does not prove atomic completeness or provenance. `content_checkpoint_captures_staged_raw_worktree_untracked_ignored_and_links_without_touching_index` checks staged versus unstaged bytes, untracked, selected ignored, executable bit, symlink target, unchanged original index, restart, Git GC and verification. No restore acceptance is claimed.

## Submission and non-publishing integration candidate

`submission create WORKSPACE --repo REPO --target refs/heads/BRANCH` records a clean RIT workspace's committed source, creation base, changed paths and observed target commit in `refs/rit/submissions/<id>/manifest` with expected-zero ref creation. It does not include ignored files or later/uncommitted changes and refuses a dirty or uninspectable source. The receipt includes an ephemeral partial source dependency graph and IDs of related content checkpoints when available. Git metadata is durable coordination but is mutable, unauthenticated and not an approval or protected audit record.

`submission candidate ID --repo REPO --path PATH` first performs a real ephemeral isolated-object merge simulation, returning structured conflicts without creating a candidate on conflict. For a clean merge it rechecks recorded source/target, repeats the restricted merge into the common Git object store, writes a two-parent synthetic merge commit and RIT-owned candidate ref, reserves a `provisioning` manifest, creates a genuine detached `--no-checkout` Git worktree at a validated owner-only location, and materializes bounded regular files without checkout hooks or filters where safe. Unsupported checkout content remains explicitly `no_checkout`. `submission candidates` reconciles paths, detached HEAD, candidate ref and target movement; interrupted provisioning and mismatches are surfaced. It never updates the target/source ref and runs no repository-provided builds/tests. Partial static dependency analysis and bounded Git fsck are returned as ephemeral results; missing/failed analysis is not a pass, commit graph/multi-pack-index are excluded from fsck, and results are neither durable validation records nor approval. Candidate worktrees are not security sandboxes. Interrupted work may leave candidate refs, directories or unreachable objects and is not automatically cleaned up.

Tests `submission_builds_real_detached_candidate_without_publishing_and_reconciles_staleness` and `conflicting_submission_reports_git_stages_and_creates_no_candidate` cover actual RIT-created source worktree, dirty refusal, two-parent candidate contents, detached inventory, unchanged target/source, hook non-execution, object/static checks, rediscovery, target movement, deleted candidate ref, Git conflict stages and refusal to create a conflicting worktree. Linux x86-64/Git 2.47.3 only; same-UID races, filesystem adversaries, platform behavior, crash recovery and independent security review remain open. Workspace reconciliation now reports `inspection_unavailable` rather than `present` when Git inspection/status cannot be obtained.
