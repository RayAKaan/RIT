# API and protocol reference — V3 development preview

No HTTP API, credentials, authenticated MCP tools, production authorization middleware or privileged routes exist. `rit mcp serve --repo PATH` and `rit-protocol --repo PATH` explicitly opt into a local newline-delimited stdio scope rooted at one selected repository. Six allowlisted read-only tools call shared application services: `repository.inspect`, `repository.status`, `repository.branches`, `repository.history`, `repository.worktrees`, and `dependencies.inspect`. Tool arguments must be empty; unsupported/mutation tools and path arguments are denied. Default unscoped server advertises no tools. Worktree inventory can report paths outside the selected root; this is observation of that Git repository, not filesystem containment.

This is an OS-user opt-in boundary, **not** authenticated RIT authorization, durable file identity, or an OS sandbox. The common Git directory is rechecked but can be replaced/raced. Stdio requests are capped at 65536 bytes; stdout is protocol messages only. Legacy and modern discovery are partial; full protocol conformance is not established. Transport-injected Rust/Python/TypeScript client tests use real stdio for scoped reads and denial, not official-client conformance. See `handoff/FINAL_REPORT.md`.
